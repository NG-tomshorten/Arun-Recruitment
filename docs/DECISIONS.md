# Decisions and trade-offs

Things that were decided the hard way, so nobody "fixes" them back. One entry per decision:
what was chosen, why, and what it costs. Newest at the bottom. Product decisions from Barry go
in PLAN.md as amendments; this file is for engineering trade-offs that PLAN.md does not cover.

## 2026-09-01 — The build script forces `NODE_ENV=production` and clears two caches

`npm run build` runs `tinacms build … -c "NODE_ENV=production next build"` and first deletes
`.next` and `tina/__generated__/.cache`, passing `--no-client-build-cache`.

- **Why:** the tinacms CLI exports `NODE_ENV=development` into the inner command, which crashes
  Next's prerendering. Separately, two cache layers (Next's and Tina's client build cache) will
  serve stale job content into a fresh build — a Barry edit that never ships.
- **Cost:** every build is a cold build. Fine at this size.

## 2026-09-01 — Verification builds run in a disposable git worktree (`npm run verify`)

- **Why:** running `npm run build` in the working tree while `npm run dev` is up deletes the
  manifests under the dev server and rewrites the generated Tina client onto the build's port,
  500ing the site until a restart. Tom usually has the dev server running.
- **How:** `scripts/verify-build.sh` adds a worktree in a temp dir, copies the uncommitted
  changes across, clones `node_modules` with `cp -Rc` (APFS copy-on-write, ~15s) and builds
  there. The clone is not a symlink because Turbopack refuses a `node_modules` symlink that
  points outside its root.
- **Cost:** ~15s and a few hundred MB of clone per run; removed on exit.

## 2026-09-02 — The home page stays minimal

Hero fork and the sea scene only; no placement cards, no credibility block, no content fetch.
Barry and Tom both prefer the near-empty landing. It also means the home page can never break
when listings change. Do not re-add sections without being asked.

## 2026-09-02 — One static OG card, no satori/sharp

`public/images/og.png` is regenerated by hand from `scripts/og-card.html` and used for every
page. Per-placement OG images would have needed satori + sharp in the tree (guardrail 2) for a
marginal gain on ten filled roles.

## 2026-09-02 — CSP `script-src` is `'unsafe-inline'`, by the plan's own fallback

The export has 139 unique inline scripts (Next's hydration payloads); Cloudflare caps a header at
2,000 characters, so hashing them all is unviable. PLAN §8.2 anticipated this fallback.
`/admin` gets its own CSP with the TinaCloud hosts from tina.io's CSP guide. Revisit only if
Next ships nonce support for static exports.

## 2026-09-02 — Five `npm audit` moderates accepted

`next` was bumped to clear six highs in bundled postcss/sharp and `qs` is pinned via
`package.json` overrides. The five remaining moderates are `react-router` inside Tina's admin SPA
— authenticated, noindexed, no SSR. The only fix is a breaking tinacms downgrade, so they are
accepted; record them in `docs/MAINTENANCE.md` at step 10.

## 2026-09-02 — Measure Lighthouse behind a compressing server

Python's `http.server` serves uncompressed and costs ~17 performance points. Use a server that
gzips (for example `npx serve out`) before trusting a score. The static export writes
`out/jobs.html` beside `out/jobs/<slug>/`, so on a dumb server request `/jobs.html`, not `/jobs/`.

## 2026-09-02 — Turnstile runs on Cloudflare's published test keys until deploy

The site key defaults to `1x00000000000000000000AA` when `NEXT_PUBLIC_TURNSTILE_SITE_KEY` is
unset, and the Worker's `.dev.vars` uses the matching test secret, so forms and Worker pass
Turnstile together locally with no real keys. Real keys land at step 8.

## 2026-09-02 — The `/profile` CV is relayed, never stored; the background question is a flag

The one file input on the site rides to Barry's inbox as a Resend attachment and is forgotten
the moment Resend accepts it (guardrail 4's single exception). The background-check question
collects "clean" or "something to disclose" with deliberately no detail field: criminal-offence
data must never transit email. Spec in the PLAN.md profile amendment.

## 2026-09-06 — Disqualifying Taiwan answers are soft flags, never dead ends

An online degree or "I'd rather teach older students" shows the candidate a one-line note and
still sends the profile with a labelled line for Barry. Barry decides; the wizard never loses a
lead. The required national check is derived from the passport country rather than asked, and
South Africa / Other (on our passport list, not in Barry's brief) get generic wording rather
than an invented check name.

## 2026-09-06 — Cards are white on chalk, not chalk on foam

PLAN §11.4 specifies chalk cards on foam sections. The pages are chalk end to end (no foam
sections survived the pivot to a minimal home page), so a chalk card on a chalk page had no edge
— the salary panel on a placement page read as a stray rectangle. Cards are now `bg-white` with
the gull hairline and haze shadow (`card` in `globals.css`), and a second recipe, `card-callout`
(foam wash, harbour border, no shadow), carries messages and single CTAs. White is Tailwind's
default token, already used for inputs; it is not added to the palette or the contrast gate
because every text colour that passes on chalk passes on white. If foam sections ever return,
`card` should go back to chalk there — one recipe, not a third.
